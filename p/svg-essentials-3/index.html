图案和渐变

图案

要使用图案，首先要定义一个水平或者垂直方向重复的图形对象，然后用它填充另一个对象或者作为笔画使用。

这个图形对象被称作 tile（瓷砖），因为使用图案填充对象的行为很像在地面上铺瓷砖的过程。

patternUnits

要创建一个图案，必须使用 <pattern> 元素包裹描述图案的 <path> 元素；然后确定如何排列图案，这一点体现在 patternUnits 属性上。

如果希望图案的尺寸基于对象的大小计算，需要指定图案左上角的 x 和 y 坐标，以及其 width 和 height（百分比或者 0 到 1 之间的小数）；然后设置 patternUnits:objectBoundingBox（边界框，默认值）。对象的边界框是一个完全包裹图形对象的最小矩形。

patternContentUnits

确定了如何排列图案（patternUnits），还要确定的是用什么单位表达图案数据本身。

默认情况下，patternContentUnits 属性值为 userSpaceOnUse。如果设置属性值为 objectBoundingBox，则路径本身的数据点会基于被填充的对象来确定。

解释一下

如果 patternContentUnits:userSpaceOnUse，那么图案的边界框左上角应该在原点 (0, 0) 位置。

如果使用 objectBoundingBox，则需要在图案中减小 stroke-width 的值。图案的宽度也会以被填充对象的边界框作为参考，而不会使用用户单位，因此 stroke-width 为 1 会覆盖整个图案。

patternUnits 与 patternContentUnits 核心区别：

  • patternUnits 决定图案本身的平铺区域（x、y、width、height）使用什么坐标系：
    • userSpaceOnUse 使用 SVG 的用户坐标系，平铺单元宽度为 0.2 个用户单位；
    • objectBoundingBox 使用被填充对象的边界框作为参考，平铺单元宽度为对象边界框宽度的 20%。
  • patternContentUnits 决定图案内部绘制的图形（例如 <path>、<circle>）使用什么坐标系：
    • userSpaceOnUse 使用 SVG 的用户坐标系，(0, 0) 就是整个 SVG 用户坐标系的原点；
    • objectBoundingBox 使用被填充对象的边界框作为参考，(0, 0) 就是被填充对象边界框的左上角。

为什么 stroke-width="1" 会覆盖整个图案？

当图案内容使用 objectBoundingBox 时，路径坐标中的 1 不再代表 1 个普通用户单位，而是边界框对应方向的完整尺寸。

路径从边界框左上角延伸到右下角。stroke-width="1" 的描边宽度也会受到坐标变换的缩放，因此会变得非常粗，达到与对象尺寸相当的量级，甚至可能遮盖图案内容。

    径向渐变的范围是由圆形（圈）确定，其中中心点为 0%，外圆周定义了点 100%

空白和文本

通过改变 xml:space 属性的值来改变 SVG 处理文本中空白字符（空格、制表符、换行符）的方式。

如果指定值为 default（默认值），则 SVG 会按如下规则处理空白字符：

  • 删除所有换行符
  • 将所有制表符转换为空格
  • 删除首尾空格
  • 将任意数量的连续空格换为一个空格

如果使用 \t 表示制表符，\n 表示换行符，下划线表示空格，则\n\n___abc_\t\t_def_\n\n__ghi会渲染成 abc_def_ghi。

xml:space 的另一个值是 preserve；使用该值时，SVG 只会简单地将所有换行符和制表符换为空格（保留首尾空格），然后显示出来。

同样的文本 \n\n___abc_\t\t_def_\n\n__ghi 会渲染成 _____abc____def_____ghi。

SVG 对空白字符的处理与 HTML 不完全一样。
  • SVG 默认会去掉所有的换行符，而 HTML 会将文本内容的换行符转换为空格；
  • preserve 会将所有换行符转换为空格，而 HTML 的 <pre> 元素并不这么处理。

警告

<marker>、<symbol> 和 <svg> 元素都会定义其自身的 ViewPort，你也可以使用 overflow:hidden 样式来裁剪 ViewPort 内容。 然而，如果内容的 meet 设置为 preserveAspectRatio，ViewPort 可能比 viewBox 更大。

要裁剪这个 viewBox，就要创建一个 <clipPath> 元素，其中包含一个匹配 viewBox 最小 x、最小 y、宽度和高度的矩形。

ViewPort 和 viewBox 不是同一个东西，因此裁剪 ViewPort 不一定等于裁剪 viewBox：

  • ViewPort 是 SVG 内容实际显示的矩形区域，例如 <svg width="200" height="100"> 建立的 200 × 100 区域。
  • viewBox 是指定 SVG 内部要映射到 ViewPort 中的用户坐标区域，例如 viewBox="0 0 100 100"。
  • preserveAspectRatio 规定 viewBox 映射到 ViewPort 时，如何处理宽高比不一致的问题。

蒙版

我们使用 <mask> 元素创建蒙版；起始 <mask> 和结束 </mask> 标记之间是我们想要用作蒙版的任意基本形状、文本、图像或者路径。

和 <pattern>、<linearGradient>、<radialGradient>、<clipPath> 一样，<mask> 也有 maskUnits 和 maskContentUnits：

属性控制内容默认值
maskUnitsx、y、width、height 使用什么坐标系objectBoundingBox
maskContentUnits蒙版内部图形使用什么坐标系userSpaceOnUse
特性objectBoundingBoxuserSpaceOnUse
坐标参考系元素自身的宽高边界盒（Bounding Box）SVG 画布的全局用户坐标系
数值范围0 ~ 1（归一化比例）绝对像素值（如 0 ~ 200px）
缩放行为随应用对象的尺寸等比例缩放固定大小，不随应用对象缩放而改变
多元素拼接各自独立渲染，边界不连贯可实现跨元素的全局无缝对齐

我们知道，每个像素由 4 个值描述，分别是红、绿、蓝颜色值和不透明度；但 SVG 没有直接使用不透明度确定蒙版透明度。

SVG 默认使用 (0.2126 * RedValue + 0.7152 * GreenValue + 0.0722 * BlueValue) * OpacityValue 计算蒙版的透明度，所有的值都是 0 到 1 之间的浮点数。

这三个系数来自 ITU-R BT.709 电视视频标准 所采用的 RGB 颜色系统，用于计算颜色的相对亮度。

SVG 支持通过 mask-type:alpha 直接使用不透明度确定蒙版透明度。

提示

SVG 中的蒙版与我们在化装舞会上戴的面具正好相反。在化装舞会上戴的面具，其不透明的部分用于遮挡我们的脸，半透明的部分让人能隐约看到我们的脸。

如果蒙版是不透明的，被蒙版覆盖的对象的像素就是不透明的；如果蒙版是半透明的，那么对象就是半透明的，蒙版的透明部分会使被覆盖对象的相应部分不可见。

书中的这段话让人摸不着头脑。可以把蒙版理解为一张灰度控制图：

  • 黑色：完全隐藏被遮罩对象；
  • 白色、不透明：完全显示被遮罩对象；
  • 灰色、半透明或灰度值较低：部分显示被遮罩对象。
