上下文切换

Since each provider has their own way of tracking tool calls and thinking traces, this can only be a best-effort thing.

文章中提到不同的 Provider 有不同的上下文格式；所以，在发生模型切换时，Pi 只能尽力而为（也就是说，做不到完美）。

仓库的 README 中有说明：

  • UserMessage 和 ToolResult 保持不变；
  • 来自相同 Provider 的 AssistantMessage 保持不变；
  • 来自不同 Provider 的 AssistantMessage 中的 ThkingBlock 会使用 <thinking> 包裹；
  • ToolCalls 和普通文本保持不变。

export const streamSimple: StreamFunction<
  'openai-responses',
  SimpleStreamOptions
> = (
  model: Model<'openai-responses'>,
  context: Context,
  options?: SimpleStreamOptions
): AssistantMessageEventStream => {
  getClientApiKey(model.provider, options?.apiKey, options?.headers);
  const base = buildBaseOptions(model, context, options, options?.apiKey);
  const clampedReasoning = options?.reasoning
    ? clampThinkingLevel(model, options.reasoning)
    : undefined;
  const reasoningEffort =
    clampedReasoning === 'off' ? undefined : clampedReasoning;

  return stream(model, context, {
    ...base,
    reasoningEffort
  } satisfies OpenAIResponsesOptions);
};
// Generate function for OpenAI Responses API
export const stream: StreamFunction<
  'openai-responses',
  OpenAIResponsesOptions
> = (
  model: Model<'openai-responses'>,
  context: Context,
  options?: OpenAIResponsesOptions
): AssistantMessageEventStream => {
  const stream = new AssistantMessageEventStream();
  (async () => {
    const output: AssistantMessage = {
      role: 'assistant',
      content: [],
      api: model.api as Api,
      provider: model.provider,
      model: model.id,
      usage: {
        input: 0,
        output: 0,
        cacheRead: 0,
        cacheWrite: 0,
        totalTokens: 0,
        cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0, total: 0 }
      },
      stopReason: 'pending',
      timestamp: Date.now()
    };
    try {
      const apiKey = getClientApiKey(
        model.provider,
        options?.apiKey,
        options?.headers
      );
      const cacheRetention = resolveCacheRetention(
        options?.cacheRetention,
        options?.env
      );
      const cacheSessionId =
        cacheRetention === 'none' ? undefined : options?.sessionId;
      const compat = getCompat(model);
      /**
       * https://developers.openai.com/api/reference/resources/$shared#(resource)%20%24shared%20%3E%20(model)%20custom_tool_input_format%20%3E%20(schema)
       * OpenAI 支持一种 grammar 约束方式，让模型按指定格式生成内容
       * {
       *   name: "generate_sql",
       *   parameters: {
       *     type: "object",
       *     properties: {
       *       query: { type: "string" }
       *     },
       *     required: ["query"]
       *   },
       *   constrainedSampling: {
       *     type: "grammar",
       *     variants: {
       *       openai_lark: "start: SELECT ..."
       *     }
       *   }
       * }
       * createGrammarToolInputProperties 返回：
       * Map { "generate_sql" => "query" }
       */
      const grammarToolInputProperties = createGrammarToolInputProperties(
        context.tools,
        compat.supportsOpenAIGrammarTools
      );
      /**
       * 判断之前的模型，并做一些处理
       * model.provider === "github-copilot"
       * model.provider === "xai"
       */
      const client = createClient(
        model,
        context,
        apiKey,
        options?.headers,
        options?.fetch,
        cacheSessionId
      );
      /**
       * 在正式调用 LLM 之前，处理参数
       * cross-provider-handoffs 就包含在 buildParams 内部
       */
      let params = buildParams(
        model,
        context,
        options,
        compat,
        grammarToolInputProperties
      );
      const nextParams = await options?.onPayload?.(params, model);
      if (nextParams !== undefined) {
        params = nextParams as ResponseCreateParamsStreaming;
      }
      const requestOptions = {
        ...(options?.signal ? { signal: options.signal } : {}),
        ...(options?.timeoutMs !== undefined
          ? { timeout: options.timeoutMs }
          : {}),
        maxRetries: 0
      };
      // 下边的逻辑就是调用 LLM、处理响应了
      const { data: openaiStream, response } = await retryProviderRequest(
        () => client.responses.create(params, requestOptions).withResponse(),
        {
          maxRetries: options?.maxRetries,
          maxRetryDelayMs: options?.maxRetryDelayMs,
          signal: options?.signal
        }
      );
      await options?.onResponse?.(
        { status: response.status, headers: headersToRecord(response.headers) },
        model
      );
      stream.push({ type: 'start', partial: output });
      await processResponsesStream(openaiStream, output, stream, model, {
        serviceTier: options?.serviceTier,
        grammarToolInputProperties,
        applyServiceTierPricing: (usage, serviceTier) =>
          applyServiceTierPricing(usage, serviceTier, model)
      });
      // 作者认为，在流式输出的过程中，如果请求被终止，应该输出不完整的消息，而非直接吞掉
      if (options?.signal?.aborted) {
        throw new Error('请求被取消');
      }
      if (output.stopReason === 'pending') {
        throw new Error('OpenAI 响应流结束但没有具体原因');
      }
      if (output.stopReason === 'aborted' || output.stopReason === 'error') {
        throw new Error(output.errorMessage || '未知错误');
      }
      stream.push({ type: 'done', reason: output.stopReason, message: output });
      stream.end();
    } catch (error) {
      for (const block of output.content) {
        delete (block as { index?: number }).index;
        // 流暂存缓冲区仅在解析期间使用
        delete (block as { partialJson?: string }).partialJson;
        delete (block as { customInput?: unknown }).customInput;
      }
      output.stopReason = options?.signal?.aborted ? 'aborted' : 'error';
      output.errorMessage = formatOpenAIResponsesError(error);
      stream.push({ type: 'error', reason: output.stopReason, error: output });
      stream.end();
    }
  })();
  return stream;
};

  context: Context,
  options: OpenAIResponsesOptions | undefined,
  compat: Required<OpenAIResponsesCompat> = getCompat(model), // 判断模型支持的特性

    string,
    string

    context.tools,
    compat.supportsOpenAIGrammarTools

    ? 'additional-tools'
    : compat.supportsToolSearch
      ? 'tool-search'
      : undefined;
  /**
   * 遍历 AssistantMessage 和 toolResult
   * 将工具分成 immediate 和 deferred

    context,
    deferredToolsMode !== undefined

  const messages = convertResponsesMessages(

    context,

      deferredToolsMode,
      toolOptions: {
        supportsStrictMode: compat.supportsStrictMode,
        supportsOpenAIGrammarTools: compat.supportsOpenAIGrammarTools
      }
    }
  );

/**
 * packages/ai/src/api/openai-responses-shared.ts
 * 消息翻译器，用来将 Pi 内部的消息格式以及别的 Model 的消息格式，翻译给 OpenAI
 */
export function convertResponsesMessages<TApi extends Api>(
  model: Model<TApi>,
  context: Context,
  allowedToolCallProviders: ReadonlySet<string>,
  options?: ConvertResponsesMessagesOptions
): ResponseInput {
  const messages: ResponseInput = [];
  const loadedToolNames = new Set<string>();
  // 同 Provider 和 API 的 ID 处理逻辑
  const normalizeIdPart = (part: string): string => {
    const sanitized = part.replace(/[^a-zA-Z0-9_-]/g, '_');
    const normalized =
      sanitized.length > 64 ? sanitized.slice(0, 64) : sanitized;
    return normalized.replace(/_+$/, '');
  };
  // 跨 Provider 和 API 的 ID 处理逻辑
  const buildForeignResponsesItemId = (itemId: string): string => {
    const normalized = `fc_${shortHash(itemId)}`;
    return normalized.length > 64 ? normalized.slice(0, 64) : normalized;
  };
  /**
   * toolCallId 可能是 callId|itemId 格式
   * OpenAI Responses API 对 ID 有要求：
   * * 只能包含 a-zA-Z0-9_-
   * * 最长 64 字符
   * * function_call item id 必须以 fc_ 开头
   * 输出处理后的 callId|itemId
   */
  const normalizeToolCallId = (
    id: string,
    _targetModel: Model<TApi>,
    source: AssistantMessage
  ): string => {
    if (!allowedToolCallProviders.has(model.provider))
      return normalizeIdPart(id);
    if (!id.includes('|')) return normalizeIdPart(id);
    const [callId, itemId] = id.split('|');
    const normalizedCallId = normalizeIdPart(callId);
    // 根据 AssistantMessage 中的 provider & api 属性判断是否是相同的 Provider
    const isForeignToolCall =
      source.provider !== model.provider || source.api !== model.api;
    // 采用不同的 ID 处理策略
    let normalizedItemId = isForeignToolCall
      ? buildForeignResponsesItemId(itemId)
      : normalizeIdPart(itemId);
    // OpenAI Responses API 需要的 itemId 是 fc 开头的
    if (!normalizedItemId.startsWith('fc_')) {
      normalizedItemId = normalizeIdPart(`fc_${normalizedItemId}`);
    }
    return `${normalizedCallId}|${normalizedItemId}`;
  };
  /**
   * 这里已经是 cross-provider-handoffs 过程的一部分了：
   * * 对不支持 image 的模型，会将 UserMessage & toolResult 中的图片替换为文本：
   * * * const NON_VISION_USER_IMAGE_PLACEHOLDER = "(image omitted: model does not support images)";
   * * * const NON_VISION_TOOL_IMAGE_PLACEHOLDER = "(tool image omitted: model does not support images)";
   * * 对 toolResult 中的 toolCallId 进行处理
   * * 对 AssistantMessage 进行处理：
   * * * 如果 thinking 是加密内容，isSameModel 就保留，反之丢弃
   * * * 如果 thinking 被签名了，保留原样，不处理；否则返回 block.thinking
   * * * 如果是 toolCall，isSameModel 就保留，反之使用 normalizeToolCallId 处理
   */
  const transformedMessages = transformMessages(
    context.messages,
    model,
    normalizeToolCallId
  );
  /**
   * 处理系统提示词（按照 OpenAI Responses API 要求）：
   * * reasoning 模型（如 o1 / o3）要求 SystemPrompt 用 developer 角色
   * * 普通模型用 system 角色
   */
  const includeSystemPrompt = options?.includeSystemPrompt ?? true;
  if (includeSystemPrompt && context.systemPrompt) {
    const compat = model.compat as
      | { supportsDeveloperRole?: boolean }
      | undefined;
    const role =
      model.reasoning && compat?.supportsDeveloperRole !== false
        ? 'developer'
        : 'system';
    messages.push({
      role,
      // 删除不成对的 Unicode 代理字符
      content: sanitizeSurrogates(context.systemPrompt)
    });
  }
  let msgIndex = 0;
  for (const msg of transformedMessages) {
    if (msg.role === 'user') {
      if (typeof msg.content === 'string') {
        messages.push({
          role: 'user',
          content: [
            { type: 'input_text', text: sanitizeSurrogates(msg.content) }
          ]
        });
      } else {
        const content: ResponseInputContent[] = msg.content.map(
          (item): ResponseInputContent => {
            if (item.type === 'text') {
              return {
                type: 'input_text',
                text: sanitizeSurrogates(item.text)
              } satisfies ResponseInputText;
            }
            return {
              type: 'input_image',
              detail: 'auto',
              image_url: `data:${item.mimeType};base64,${item.data}`
            } satisfies ResponseInputImage;
          }
        );
        if (content.length === 0) continue;
        messages.push({
          role: 'user',
          content
        });
      }
    } else if (msg.role === 'assistant') {
      const output: ResponseInput = [];
      const assistantMsg = msg as AssistantMessage;
      const isSameProviderAndApi =
        assistantMsg.provider === model.provider &&
        assistantMsg.api === model.api;
      const isSameModel =
        isSameProviderAndApi && assistantMsg.model === model.id;
      const isDifferentModel =
        isSameProviderAndApi && assistantMsg.model !== model.id;
      let textBlockIndex = 0;
      for (const block of msg.content) {
        if (block.type === 'thinking') {
          if (block.thinkingSignature) {
            const reasoningItem = JSON.parse(
              block.thinkingSignature
            ) as ResponseReasoningItem;
            output.push(reasoningItem);
          }
        } else if (block.type === 'text') {
          const textBlock = block as TextContent;
          const parsedSignature = parseTextSignature(textBlock.textSignature);
          const fallbackMessageId =
            textBlockIndex === 0
              ? `msg_pi_${msgIndex}`
              : `msg_pi_${msgIndex}_${textBlockIndex}`;
          textBlockIndex++;
          // OpenAI requires id to be max 64 characters
          let msgId = parsedSignature?.id;
          if (!msgId) {
            msgId = fallbackMessageId;
          } else if (msgId.length > 64) {
            msgId = `msg_${shortHash(msgId)}`;
          }
          output.push({
            type: 'message',
            role: 'assistant',
            content: [
              {
                type: 'output_text',
                text: sanitizeSurrogates(textBlock.text),
                annotations: []
              }
            ],
            status: 'completed',
            id: msgId,
            phase: parsedSignature?.phase
          } satisfies ResponseOutputMessage);
        } else if (block.type === 'toolCall') {
          const toolCall = block as ToolCall;
          const [callId, itemIdRaw] = toolCall.id.split('|');
          const customInputProperty = options?.grammarToolInputProperties?.get(
            toolCall.name
          );
          let itemId: string | undefined = itemIdRaw;
          /**
           * OpenAI 会追踪那些与 rs_xxx 推理项匹配的 fc_xxx ID
           * 将 ID 设置为 undefined 可以避免匹配校验
           * 将 custom-tool calls 重放为 function_call 时：
           * * 丢弃不是 fc_xxx ID 的 custom-tool（例如，ctc_xxx）
           * * 因为 function_call 的 ID 必须是 fc_xxx
           */
          if (
            (isDifferentModel && itemId?.startsWith('fc_')) ||
            (customInputProperty === undefined && !itemId?.startsWith('fc_'))
          ) {
            itemId = undefined;
          }
          const canReplayNamespace =
            isSameModel || options?.deferredTools?.has(toolCall.name) === true;
          if (customInputProperty !== undefined) {
            //  grammar 工具 → custom_tool_call
            output.push({
              type: 'custom_tool_call',
              id: itemId,
              call_id: callId,
              name: toolCall.name,
              input: sanitizeSurrogates(
                getGrammarToolInput(
                  toolCall.name,
                  toolCall.arguments,
                  customInputProperty
                )
              ),
              ...(canReplayNamespace && toolCall.namespace !== undefined
                ? { namespace: toolCall.namespace }
                : {})
            } satisfies ResponseOutputItem);
          } else {
            // 普通工具 → function_call
            output.push({
              type: 'function_call',
              id: itemId,
              call_id: callId,
              name: toolCall.name,
              arguments: JSON.stringify(toolCall.arguments),
              ...(canReplayNamespace && toolCall.namespace !== undefined
                ? { namespace: toolCall.namespace }
                : {})
            });
          }
        }
      }
      if (output.length === 0) continue;
      messages.push(...output);
    } else if (msg.role === 'toolResult') {
      const [callId] = msg.toolCallId.split('|');
      const output = convertToolResultOutput(model, msg.content);
      if (options?.grammarToolInputProperties?.has(msg.toolName)) {
        // grammar 工具 → custom_tool_call_output
        messages.push({
          type: 'custom_tool_call_output',
          call_id: callId,
          output
        });
      } else {
        // 普通工具 → function_call_output
        messages.push({
          type: 'function_call_output',
          call_id: callId,
          output
        });
      }
      const deferredTools: Tool[] = [];
      for (const name of msg.addedToolNames ?? []) {
        const tool = options?.deferredTools?.get(name);
        if (!tool || loadedToolNames.has(name)) continue;
        loadedToolNames.add(name);
        deferredTools.push(tool);
      }
      if (
        deferredTools.length > 0 &&
        options?.deferredToolsMode === 'additional-tools'
      ) {
        // 插入 additional_tools 消息，让模型知道新增了工具
        messages.push({
          type: 'additional_tools',
          role: 'developer',
          tools: convertResponsesTools(deferredTools, options.toolOptions)
        } satisfies ResponseInputItem);
      } else if (
        deferredTools.length > 0 &&
        options?.deferredToolsMode === 'tool-search'
      ) {
        // 模拟一次 tool_search_call + tool_search_output，让客户端加载工具
        const names = deferredTools.map(tool => tool.name);
        const searchCallId = `pi_tool_load_${shortHash(`${msg.toolCallId}:${names.join(',')}`)}`;
        messages.push({
          type: 'tool_search_call',
          call_id: searchCallId,
          execution: 'client',
          status: 'completed',
          arguments: { query: names.join(' '), limit: names.length }
        } satisfies ResponseInputItem);
        messages.push({
          type: 'tool_search_output',
          call_id: searchCallId,
          execution: 'client',
          status: 'completed',
          tools: convertResponsesTools(deferredTools, {
            ...options.toolOptions,
            deferLoading: true
          })
        } satisfies ResponseToolSearchOutputItemParam);
      }
    }
    msgIndex++;
  }
  return messages;
}

每个 Model 都有自己的 Provider，每个 Provider 都有自己的 streamSimple / stream，都调用了自己的 buildParams 工具函数来将上下文翻译给 LLM；所以，代码里并没有单独的 cross-provider-handoffs 模块，都是 Provider 在处理上下文时，自动处理的。

这样就保证了上下文在接入不同的 LLM 时，都能正常工作；但作者也表示「a best-effort thing」，毕竟在“翻译”的过程中，会 drop 掉一些只有原 Provider 才能理解的内部标识符（元数据）。

const CHARS_PER_TOKEN = 4; // 假设每 4 个字符为 1 个 token
const ESTIMATED_IMAGE_CHARS = 4800; // 假设图片为 4800 个字符
// 上下文 token 计算
export function calculateContextTokens(usage: Usage): number {
  return (
    usage.totalTokens ||
    /**
     * KV Cache 是 LLM 领域的概念，所以这里不是指 KV Cache（虽然单位也是 token）:
     * * usage.cacheRead + usage.cacheWrite 指的是 Provider 的 PromptCache
     * * PromptCache 是商业计费概念，在多轮请求中复用前面不变的提示部分（省钱 + 提速）
     * ---------------------------------
     * 例如 Anthropic 的 PromptCaching：
     * * input      不命中缓存的普通输入 token
     * * cacheRead  后续请求命中缓存时读的 token 数
     * * cacheWrite 第一次把 Prompt 写进缓存时的 token 数
     * --------------------------------------------------
     * [Agent 客户端]
     *      │  发送请求（包含 10k Token 的固定 SystemPrompt）
     *      ▼
     * [API Gateway / PromptCache 路由层]
     *      │  1. 计算前缀 Token 的 Hash 值
     *      │  2. 匹配到已有 Cache 记录（Cache Hit）
     *      ▼
     * [LLM 推理集群（GPU 显存）]
     *      │  3. 直接读取显存中早已计算好的 KV Cache Tensor
     *      │  4. 跳过这 10k Token 的 Prefill 矩阵计算，仅对新增 Token 做解码
     *      ▼
     * [返回 Agent 客户端]
     *      │  计费账单显示：10k Tokens -> Cache Read（价格仅为 StandardInput 的 10%）
     * -------------------------------------------------------------------------------
     * 官方博客 https://earendil.com/posts/prompt-caching 里提到一些会影响 PromptCache 的行为：
     * 1. KV Cache 保存在 Provider 的服务端，会有一定的生效时间，会话超过一定时间没有被激活，缓存就会失效
     * 2. 在同一个 Session 过程中切换 Model 或者 Provider，毕竟 KV Cache 是保存在 LLM 云端的
     * 3. 通过 /tree 切换 SessionBranch，SessionBranch 对应的 Context 和 KV Cache 对应不上
     * 4. 上下文压缩，因为 KV Cache 和 ContextHistory 需要相对应的
     * 5. 工具 / 推理级别，因为这两者本身就是 Context 的一部分
     * 6. 动态 SystemPrompt，Context 会不稳定，KV Cache 没意义
     * 7. 会修改 Context 的 Extension 的使用
     * 8. 即使是相同的 Provider 和 Model，但远程的 Route 策略不稳定：
     *    * 负载均衡的时候，把请求指向了没有保存对应 KV Cache 的 Worker
     *    * 内存有限，被别的请求的 KV Cache 挤占，自己的被销毁
     */
    usage.input + usage.output + usage.cacheRead + usage.cacheWrite
  );
}
function estimateTextAndImageContentChars(
  content: string | Array<TextContent | ImageContent>
): number {
  if (typeof content === 'string') return content.length;
  let chars = 0;
  for (const block of content)
    chars += block.type === 'text' ? block.text.length : ESTIMATED_IMAGE_CHARS;
  return chars;
}
export function estimateTextTokens(text: string): number {
  return Math.ceil(text.length / CHARS_PER_TOKEN);
}
export function estimateTextAndImageContentTokens(
  content: string | Array<TextContent | ImageContent>
): number {
  return Math.ceil(estimateTextAndImageContentChars(content) / CHARS_PER_TOKEN);
}
// 计算单条 message 的 token 量
export function estimateMessageTokens(message: Message): number {
  let chars = 0;
  if (message.role === 'user')
    return estimateTextAndImageContentTokens(message.content);
  if (message.role === 'toolResult')
    return estimateTextAndImageContentTokens(message.content);
  for (const block of message.content) {
    if (block.type === 'text') {
      chars += block.text.length;
    } else if (block.type === 'thinking') {
      chars += block.thinking.length;
    } else {
      chars += block.name.length + safeJsonStringify(block.arguments).length;
    }
  }
  return Math.ceil(chars / CHARS_PER_TOKEN);
}
// Provider 一般会在 AssistantMessage 中带上 usage 信息
function getLastAssistantUsageInfo(
  messages: readonly Message[]
): { usage: Usage; index: number } | undefined {
  let latestPrefixTimestamp = Number.NEGATIVE_INFINITY;
  let usageInfo: { usage: Usage; index: number } | undefined;
  for (let i = 0; i < messages.length; i++) {
    const message = messages[i];
    if (message.role === 'assistant') {
      const assistant = message as AssistantMessage;
      /**
       * 不明白，为什么不从后向前遍历？
       * * [compaction summary]   ← timestamp = 压缩发生的时间，较新
       * * [assistant A]          ← timestamp = 压缩前，旧
       * * [user B]               ← timestamp = 压缩前，旧
       * * [assistant C]          ← timestamp = 压缩后，最新
       * 数组顺序 !== timestamp 顺序，C 能代表压缩后的 usage
       * 这里还是没有理解！！！
       */
      const usageAppliesToPrefix = assistant.timestamp >= latestPrefixTimestamp;
      if (
        usageAppliesToPrefix &&
        assistant.stopReason !== 'aborted' &&
        assistant.stopReason !== 'error' &&
        calculateContextTokens(assistant.usage) > 0
      ) {
        usageInfo = { usage: assistant.usage, index: i };
      }
    }
    latestPrefixTimestamp = Math.max(latestPrefixTimestamp, message.timestamp);
  }
  return usageInfo;
}
function estimateMessages(messages: readonly Message[]): ContextUsageEstimate {
  const usageInfo = getLastAssistantUsageInfo(messages);
  if (usageInfo) {
    const usageTokens = calculateContextTokens(usageInfo.usage);
    let trailingTokens = 0;
    // 计算有效 AssistantMessage 之后的 token 用量
    for (let i = usageInfo.index + 1; i < messages.length; i++) {
      trailingTokens += estimateMessageTokens(messages[i]);
    }
    return {
      tokens: usageTokens + trailingTokens,
      usageTokens,
      trailingTokens,
      lastUsageIndex: usageInfo.index
    };
  }
  let tokens = 0;
  for (const message of messages) tokens += estimateMessageTokens(message);
  return {
    tokens,
    usageTokens: 0,
    trailingTokens: tokens,
    lastUsageIndex: null
  };
}
function estimateToolsTokens(tools: readonly Tool[] | undefined): number {
  if (!tools || tools.length === 0) return 0;
  return estimateTextTokens(safeJsonStringify(tools));
}
export function estimateContextTokens(
  context: Context | readonly Message[]
): ContextUsageEstimate {
  if (isMessageArray(context)) return estimateMessages(context);
  const estimate = estimateMessages(context.messages);
  if (estimate.lastUsageIndex !== null) {
    const addedNames = new Set(
      context.messages
        .slice(estimate.lastUsageIndex + 1)
        .filter(message => message.role === 'toolResult')
        .flatMap(message => message.addedToolNames ?? [])
    );
    const addedToolTokens = estimateToolsTokens(
      context.tools?.filter(tool => addedNames.has(tool.name))
    );
    return {
      tokens: estimate.tokens + addedToolTokens,
      usageTokens: estimate.usageTokens,
      trailingTokens: estimate.trailingTokens + addedToolTokens,
      lastUsageIndex: estimate.lastUsageIndex
    };
  }
  const prefixTokens =
    (context.systemPrompt ? estimateTextTokens(context.systemPrompt) : 0) +
    estimateToolsTokens(context.tools);
  return {
    tokens: estimate.tokens + prefixTokens,
    usageTokens: estimate.usageTokens,
    trailingTokens: estimate.trailingTokens + prefixTokens,
    lastUsageIndex: estimate.lastUsageIndex
  };
}

为什么开发 pi-tui？

明明有现成的第三方 TUI 库可以使用。

I definitely don’t want to write my TUI like a React app. Also, writing my own TUI framework on top of Node.js seemed like a fun little challenge.

作者不想以写 React 的方式写 TUI。TUI 的实现有两种方式：

One is to take ownership of the terminal viewport and treat it like a pixel buffer. I call these full screen TUIs. The drawback is that you lose the scrollback buffer. While this is not hard to implement, it means you have to re-implement all the functionality your terminal emulator already provides.

第一种实现方式是，接管整个 Terminal Viewport。你需要重新实现终端模拟器已经实现的所有功能：内容搜索、滚动模拟…例如，Amp、OpenCode。

The second approach is to just write to the terminal like any CLI program, appending content to the scrollback buffer, only occasionally moving the “rendering cursor” back up a little within the visible viewport to redraw things like animated spinners or a text edit field. It’s not exactly that simple, but you get the idea.

第二种实现方式是，像一个 CLI 程序，不断向 Scrollback Buffer 追加内容；只需要调整「渲染锚点」的位置做界面更新即可…例如，Claude Code、Codex。

现在的 Agent in Terminal 似乎都是第二种；退出 Agent 之后，消息渲染记录还是存在于 Terminal 之中；但是工具属性比较强的 Terminal 工具，似乎是用第一种实现方式的居多，比如 lazygit。

关于 “rendering cursor”，不知道理解成「渲染更新锚点」对不对；毕竟，“那个闪烁的文本输入光标”和视图更新毫无关系。

在 ANSI 转义序列（Terminal Escape Codes）的标准规范中，用来控制屏幕打印位置的指令统一被称为 Cursor Position Sequence（例如\x1b[nA表示向上移动 Cursor $n$ 行）。

在终端的底层视角中，并没有独立的“输入光标”和“绘制画笔”之分；终端只有唯一一个“光标位置记录器”（Cursor Vector）：

  • 当你输入文本时，光标指示你下一个字符落在哪；
  • 当你使用 ANSI 码写 CLI 界面时，也是通过向终端发送 \x1b[nA / \x1b[nG 指令，把这个“光标 / 画笔”移动回几行前的某个位置，然后覆写旧文本。

所以，“rendering cursor” 在这里指的是，控制 ANSI 打印流重新定位的那个“逻辑画笔 / 游标”。

Retained / Immediate Mode UI

If you’ve done any GUI programming, you’ve probably heard of retained mode vs immediate mode.

In a retained mode UI, you build up a tree of components that persist across frames. Each component knows how to render itself and can cache its output if nothing changed.

In an immediate mode UI, you redraw everything from scratch each frame (though in practice, immediate mode UIs also do caching, otherwise they’d fall apart).

Retained Mode 似乎就是现在前端框架的思路，组件树存在于内存中；组件内状态不变，就复用上一帧缓存的渲染结果。

Immediate Mode 类似于前端 Canvas，每一帧（Frame）从头到尾重画一遍（在底层硬件与渲染管线层面，也是有缓存机制的）。

pi-tui 是 Retained Mode，组件就是一个有 render 和 handleInput 方法的对象：

  • render 返回Array<string>，每个 arrayItem 代表一行；
  • handleInput 处理键盘输入。

差分渲染

When the TUI needs to update the screen, it asks each component to render.

Components can cache their output: an assistant message that’s fully streamed doesn’t need to re-parse markdown and re-render ANSI sequences every time. It just returns the cached lines. Containers collect lines from all children. The TUI gathers all these lines and compares them to the lines it previously rendered for the previous component tree. It keeps a backbuffer of sorts, remembering what was written to the scrollback buffer.

需要更新屏幕的时候，组件调用 render 输出结果；Containers 会收集所有子组件的渲染结果。TUI 会将这些结果和上次渲染的结果做对比（类似 React 的 current / workInProgress 树），workInProgress 被 TUI 称为 backbuffer，对比过程就是 diff 过程：

  • 内容完全一致，不向 stdout 发送任何 ANSI 指令，视图不发生变化；
  • 内容变了，发送 ANSI 光标移动指令 \x1b[nA 跳到这一行，擦除这一行 \x1b[2K，重写新文本。

这个更新过程，作者称为 differential rendering 差分渲染。

作者在文章中，简单概括了一些具体的算法思想：

  1. First render: Just output all lines to the terminal
  2. Width changed: Clear screen completely and re-render everything (soft wrapping changes)
  3. Normal update: Find the first line that differs from what’s on screen, move the cursor to that line, and re-render from there to the end

  invalidate(): void {
    for (const child of this.children) {
      child.invalidate?.();
    }
  }
  /**
   * Container 似乎并没有「收集」子组件的渲染结果
   * 而是直接调用他们的 render 方法，将结果保存下来
   */
  render(width: number): string[] {
    const lines: string[] = [];
    for (const child of this.children) {
      const childLines = child.render(width);
      for (const line of childLines) {
        lines.push(line);
      }
    }
    return lines;
  }
}

export class TuiMainScreen extends TuiBase implements TUI {
  // ...
  protected doRender(): void {
    if (this.stopped) return;
    // 检测外部尺寸是否变化
    const width = this.terminal.columns;
    const height = this.terminal.rows;
    const widthChanged =
      this.previousWidth !== 0 && this.previousWidth !== width;
    const heightChanged =
      this.previousHeight !== 0 && this.previousHeight !== height;
    // 计算之前的 bufferHeight
    const previousBufferLength =
      this.previousHeight > 0
        ? this.previousViewportTop + this.previousHeight
        : height;
    let prevViewportTop = heightChanged
      ? Math.max(0, previousBufferLength - height)
      : this.previousViewportTop;
    let viewportTop = prevViewportTop;
    let hardwareCursorRow = this.hardwareCursorRow;
    // 计算行数变化
    const computeLineDiff = (targetRow: number): number => {
      const currentScreenRow = hardwareCursorRow - prevViewportTop;
      const targetScreenRow = targetRow - viewportTop;
      return targetScreenRow - currentScreenRow;
    };
    /**
     * 渲染组件，拿到新的渲染结果
     * 就是刚刚 Container 的 render 方法返回的数组
     */
    let newLines = this.render(width);
    if (this.hasOverlayEntries) {
      // 如果是有弹窗的情况，需要计算和修改 newLines
      newLines = this.compositeOverlays(newLines, width, height);
    }
    /**
     * 在可视区域找到锚点 CURSOR_MARKER（\x1b_pi:c\x07）的位置
     * CURSOR_MARKER 是一个被终端忽略的零宽度转义序列（隐形占位符）：
     * * \x1b_ -> 专门用来向终端传递应用程序自定义的私有指令
     * * pi:c  -> 私有命名空间，pi-tui 专属的 Cursor 标记，不会与普通的文本或其它 ANSI 样式冲突
     * * \x07  -> ST（String Terminator / 响铃符）用于标记 APC 命令的结束
     * ------------------------------------------------------------------
     * 终端硬件光标的最终落点，则由 TUI 引擎在全局 diff 完成后统一精准放置：
     * * 一个 Input 组件只知道自己在当前组件树的相对位置，它根本不知道上面有多少行历史消息、右边有多少 Padding
     * * 如果页面上有两个输入框或者一个 Spinner，各个组件各自发送光标移动指令，硬件光标就会在屏幕上剧烈跳动
     * ------------------------------------------------------------ ---------------------------------------
     * 当某个组件（例如一个获取了焦点的 Editor）渲染自己时，它不需要计算复杂的物理行号和列号
     * 它只需要在自己的文本字符串里、光标应该出现的位置，插入这个特殊的 CURSOR_MARKER 字符
     * const text = "Hello" + CURSOR_MARKER + "World";
     * -----------------------------------------------
     * 当 TUI 收集完所有组件的文本行、准备刷给终端前，它会做一个全局扫描：
     * 1. 逐行扫描即将输出的文本，一旦找到了 CURSOR_MARKER 标记
     *    顺着它所在的行号和列号，立刻计算出了硬件光标在物理屏幕上的绝对坐标 (X, Y)
     *
     * 2. 把这个标记从字符串里安全删掉。因为它是“零宽度”的，删掉后完全不影响组件的布局和对齐
     *
     * 3. 把无污染的纯干净文本刷给终端，最后统一发送一条 ANSI 指令：\x1b[Y;XH
     *    把终端的硬件光标精确指到那个位置，并开启光标显示 \x1b[?25h
     */
    const cursorPos = this.extractCursorPosition(newLines, height);
    /**
     * 在每行末尾追加 SEGMENT_RESET（\x1b[0m\x1b]8;;\x07）：
     * * 如果 Line 0 渲染了一个红色的组件，但在行末没有闭合，Line 1 会自动继承 Line 0 的红色
     * * 在每一行行末强行追加 SEGMENT_RESET，确保了每一行在逻辑上都是样式自治、互不污染的
     * * 每行末尾都有确定的状态，diff 就可以安全地单独抽取某一行进行替换 / 重绘
     */
    newLines = this.applyLineResets(newLines);
    // 渲染函数，clear 表示「是否清屏」
    const fullRender = (clear: boolean): void => {
      this.fullRedrawCount += 1;
      let buffer = '\x1b[?2026h'; // 开启同步刷新模式
      if (clear) {
        buffer += this.deleteKittyImages(this.previousKittyImageIds);
        /**
         * 相当于 console.clear() 或者 clear bash 命令
         * * \x1b[2J 清空当前屏幕可见区域，Viewport 内显示的所有字符，将其全变成空白
         * * \x1b[H  光标复位到原点（屏幕最左上角（第 1 行，第 1 列））
         * * \x1b[3J 彻底清空历史滚动缓冲区（Scrollback Buffer）
         *           滚动条直接消失，历史记录全部从内存中被物理删除
         */
        buffer += '\x1b[2J\x1b[H\x1b[3J';
      }
      for (let i = 0; i < newLines.length; i++) {
        if (i > 0) buffer += '\r\n';
        const line = newLines[i];
        const isImage = isImageLine(line);
        const imageReservedRows = isImage
          ? this.getKittyImageReservedRows(newLines, i)
          : 1;
        if (imageReservedRows > 1 && imageReservedRows <= height) {
          for (let row = 1; row < imageReservedRows; row++) {
            buffer += '\r\n';
          }
          buffer += `\x1b[${imageReservedRows - 1}A`;
          buffer += line;
          buffer += `\x1b[${imageReservedRows - 1}B`;
          i += imageReservedRows - 1;
          continue;
        }
        buffer += line;
      }
      buffer += '\x1b[?2026l'; // 数据已经全部更新完毕
      this.terminal.write(buffer);
      this.cursorRow = Math.max(0, newLines.length - 1);
      this.hardwareCursorRow = this.cursorRow;
      // 更新 maxLinesRendered，diff 过程有用到
      if (clear) {
        this.maxLinesRendered = newLines.length;
      } else {
        this.maxLinesRendered = Math.max(
          this.maxLinesRendered,
          newLines.length
        );
      }
      // 为下一次渲染做准备
      const bufferLength = Math.max(height, newLines.length);
      this.previousViewportTop = Math.max(0, bufferLength - height);
      this.positionHardwareCursor(cursorPos, newLines.length);
      this.previousLines = newLines;
      this.previousKittyImageIds = this.collectKittyImageIds(newLines);
      this.previousWidth = width;
      this.previousHeight = height;
    };
    // 第一次渲染，不需要 clear
    if (this.previousLines.length === 0 && !widthChanged && !heightChanged) {
      fullRender(false);
      return;
    }
    // 宽度变化，会影响换行，整个重新渲染，需要 clear
    if (widthChanged) {
      fullRender(true);
      return;
    }
    /**
     * 高度变化，通常情况下需要全量重新渲染：
     * * 可见视口（Visible Viewport）变化，之前的多行擦除指令（如 \x1b[nA 向上移动 n 行）会直接算错距离
     * 但在 Termux（一款手机端 Terminal），软键盘高度的变化会影响 Viewport 的高度
     * 这里是对 Termux 做了兼容处理，防止软键盘造成渲染闪烁（频繁重绘）
     */
    if (heightChanged && !isTermuxSession()) {
      fullRender(true);
      return;
    }
    /**
     * 开启 PI_CLEAR_ON_SHRINK & 内容高度缩水 & 没有弹窗浮层 => 清屏重绘
     * 可能发生了内容折叠，导致高度塌陷（新的内容比上一帧的内容高度小）
     * 在没有弹窗浮层的情况下，需要清理掉塌陷的「脏行」
     * 因为弹窗浮层需要有足够的空间渲染，所以做了判断
     */
    if (
      this.getClearOnShrink() &&
      // 当前这一帧组件树渲染出来的最新总行数 < 之前渲染周期中记录到的最大占用行数
      newLines.length < this.maxLinesRendered &&
      !this.hasOverlayEntries
    ) {
      fullRender(true);
      return;
    }
    let firstChanged = -1;
    let lastChanged = -1;
    const maxLines = Math.max(newLines.length, this.previousLines.length);
    /**
     * 通过 for 循环，逐行对比，没有就用 "" 代替
     * 找出发生变化的第一行和最后一行
     * 这里算是差分渲染的核心逻辑
     */
    for (let i = 0; i < maxLines; i++) {
      const oldLine =
        i < this.previousLines.length ? this.previousLines[i] : '';
      const newLine = i < newLines.length ? newLines[i] : '';
      if (oldLine !== newLine) {
        if (firstChanged === -1) {
          firstChanged = i;
        }
        lastChanged = i;
      }
    }
    // 追加的情况，前边的没变化
    const appendedLines = newLines.length > this.previousLines.length;
    if (appendedLines) {
      if (firstChanged === -1) {
        firstChanged = this.previousLines.length;
      }
      lastChanged = newLines.length - 1;
    }
    // Kitty 图片可能跨越多行，只重绘变化的那一行会导致图片残影或撕裂
    if (firstChanged !== -1) {
      const expandedRange = this.expandChangedRangeForKittyImages(
        firstChanged,
        lastChanged,
        newLines
      );
      firstChanged = expandedRange.firstChanged;
      lastChanged = expandedRange.lastChanged;
    }
    // 纯粹的尾部追加，旧的没有变化
    const appendStart =
      appendedLines &&
      firstChanged === this.previousLines.length &&
      firstChanged > 0;
    // 新旧内容完全一致，更新物理光标位置（用户可能改变了光标位置）
    if (firstChanged === -1) {
      this.positionHardwareCursor(cursorPos, newLines.length);
      this.previousViewportTop = prevViewportTop;
      this.previousHeight = height;
      return;
    }
    // 有删除内容的情况发生
    if (firstChanged >= newLines.length) {
      // 内容变少了
      if (this.previousLines.length > newLines.length) {
        /**
         * \x1b[?2026h 表示开启同步刷新模式
         * 通常情况下，终端处理字节流时，是边接收边绘制到屏幕上的
         *   如果重绘频率很高：打字流式输出、清屏重绘（fullRender(true)）
         *   可能会有，屏幕上下半部分更新不同步导致的画面撕裂 / 剧烈闪烁
         * 开启同步刷新模式之后，会开启底层的帧缓冲区
         *   当接收到 \x1b[?2026l 时，表示数据已经全部更新完毕
         *   此时，缓冲区的数据将被一次性的更新到屏幕上
         */
        let buffer = '\x1b[?2026h';
        buffer += this.deleteChangedKittyImages(firstChanged, lastChanged);
        // 新的内容的行数
        const targetRow = Math.max(0, newLines.length - 1);
        // 内容比原来的少，清屏重绘
        if (targetRow < prevViewportTop) {
          fullRender(true);
          return;
        }
        // 计算行数变化
        const lineDiff = computeLineDiff(targetRow);
        if (lineDiff > 0)
          buffer += `\x1b[${lineDiff}B`; // 控制光标垂直向下移动 lineDiff 行
        else if (lineDiff < 0) buffer += `\x1b[${-lineDiff}A`; // 控制光标垂直向上移动 lineDiff 行
        buffer += '\r';
        // 存在多余的脏行，清屏重绘
        const extraLines = this.previousLines.length - newLines.length;
        if (extraLines > height) {
          fullRender(true);
          return;
        }
        // newLines.length === 0，新内容完全为空
        const clearStartOffset = newLines.length === 0 ? 0 : 1;
        if (extraLines > 0 && clearStartOffset > 0) {
          buffer += `\x1b[${clearStartOffset}B`; // 光标下移 1 行
        }
        // 将多余的内容擦除
        for (let i = 0; i < extraLines; i++) {
          /**
           * \r      回车符，将光标拉回当前行的最左端
           * \x1b[0K 从当前光标位置擦除到行尾
           * \x1b[1K 从行首擦除到当前光标位置
           * \x1b[2K 清空当前一整行，无论光标此刻在这一行的哪个位置
           */
          buffer += '\r\x1b[2K'; // 单行彻底清空重置
          if (i < extraLines - 1) buffer += '\x1b[1B'; // 光标接着往下移
        }
        const moveBack = Math.max(0, extraLines - 1 + clearStartOffset);
        if (moveBack > 0) {
          buffer += `\x1b[${moveBack}A`;
        }
        buffer += '\x1b[?2026l'; // 数据已经全部更新完毕
        this.terminal.write(buffer); // 将 buffer 同步到终端
        this.cursorRow = targetRow;
        this.hardwareCursorRow = targetRow;
      }
      // 更新状态，为下一次渲染做准备（WIP -> current）
      this.positionHardwareCursor(cursorPos, newLines.length);
      this.previousLines = newLines;
      this.previousKittyImageIds = this.collectKittyImageIds(newLines);
      this.previousWidth = width;
      this.previousHeight = height;
      this.previousViewportTop = prevViewportTop;
      return;
    }
    /**
     * 差分渲染只能更新当前屏幕上的内容
     * 如果本次更新涉及到了 Scrollback Buffer
     * 需要清屏重绘
     */
    if (firstChanged < prevViewportTop) {
      fullRender(true);
      return;
    }
    /**
     * 走到这里，说明：
     * 1. 非首次渲染
     * 2. 外部宽度没有变化
     * 3. 外部高度没有变化
     * 4. 不属于「开启 PI_CLEAR_ON_SHRINK & 内容高度缩水 & 没有弹窗浮层」
     * 5. 新旧内容不完全一致
     * 6. 内容没有变少（新内容比旧内容少）
     * 7. 没有涉及到 Scrollback Buffer 滚动区域的更新
     */
    let buffer = '\x1b[?2026h'; // Begin synchronized output
    buffer += this.deleteChangedKittyImages(firstChanged, lastChanged);
    const prevViewportBottom = prevViewportTop + height - 1;
    /**
     * 纯粹的尾部追加，旧的没有变化
     * 光标移动到插入位置
     */
    const moveTargetRow = appendStart ? firstChanged - 1 : firstChanged;
    if (moveTargetRow > prevViewportBottom) {
      const currentScreenRow = Math.max(
        0,
        Math.min(height - 1, hardwareCursorRow - prevViewportTop)
      );
      const moveToBottom = height - 1 - currentScreenRow;
      if (moveToBottom > 0) {
        buffer += `\x1b[${moveToBottom}B`;
      }
      const scroll = moveTargetRow - prevViewportBottom;
      buffer += '\r\n'.repeat(scroll); // 添加换行符
      prevViewportTop += scroll;
      viewportTop += scroll;
      hardwareCursorRow = moveTargetRow;
    }
    // 计算行数变化
    const lineDiff = computeLineDiff(moveTargetRow);
    if (lineDiff > 0) {
      buffer += `\x1b[${lineDiff}B`; // 行数变多向下移
    } else if (lineDiff < 0) {
      buffer += `\x1b[${-lineDiff}A`; // 行数变少向上移
    }
    buffer += appendStart ? '\r\n' : '\r';
    /**
     * 更新 firstChanged 到 lastChanged 之间的内容
     * 可以减少单行变更的闪烁行为（例如，Spinner）
     */
    const renderEnd = Math.min(lastChanged, newLines.length - 1);
    for (let i = firstChanged; i <= renderEnd; i++) {
      if (i > firstChanged) buffer += '\r\n';
      const line = newLines[i];
      const isImage = isImageLine(line);
      const imageReservedRows = isImage
        ? this.getKittyImageReservedRows(newLines, i, renderEnd)
        : 1;
      if (imageReservedRows > 1) {
        const imageStartScreenRow = i - viewportTop;
        if (
          imageStartScreenRow < 0 ||
          imageStartScreenRow + imageReservedRows > height
        ) {
          fullRender(true);
          return;
        }
        buffer += '\x1b[2K';
        for (let row = 1; row < imageReservedRows; row++) {
          buffer += '\r\n\x1b[2K';
        }
        buffer += `\x1b[${imageReservedRows - 1}A`;
        buffer += line;
        buffer += `\x1b[${imageReservedRows - 1}B`;
        i += imageReservedRows - 1;
        continue;
      }
      buffer += '\x1b[2K';
      /**
       * 单行文本宽度超出终端物理列数（visibleWidth > width）
       * 终端中，「单行溢出会直接引发链式崩溃」：
       * * 终端有“自动硬折行（Auto Hard Wrap）”机制
       * * 逻辑行与物理行的“空间撕裂”
       * * 坐标系统全面失控
       */
      if (!isImage && visibleWidth(line) > width) {
        // ...，一些崩溃日志的写入逻辑
        this.stop(); // 跳出 raw mode
        // ...，一些报错逻辑
      }
      buffer += line;
    }
    // 光标最终的位置
    let finalCursorRow = renderEnd;
    // 之前的旧内容比新内容更多，删除之后，移回光标
    if (this.previousLines.length > newLines.length) {
      // 先将光标向下移到新内容末尾
      if (renderEnd < newLines.length - 1) {
        const moveDown = newLines.length - 1 - renderEnd;
        buffer += `\x1b[${moveDown}B`;
        finalCursorRow = newLines.length - 1;
      }
      // 删除多余内容
      const extraLines = this.previousLines.length - newLines.length;
      for (let i = newLines.length; i < this.previousLines.length; i++) {
        buffer += '\r\n\x1b[2K';
      }
      // 将光标移回去
      buffer += `\x1b[${extraLines}A`;
    }
    buffer += '\x1b[?2026l';
    this.terminal.write(buffer);
    // 为下一次渲染做准备
    this.cursorRow = Math.max(0, newLines.length - 1);
    this.hardwareCursorRow = finalCursorRow;
    this.maxLinesRendered = Math.max(this.maxLinesRendered, newLines.length);
    this.previousViewportTop = Math.max(
      prevViewportTop,
      finalCursorRow - height + 1
    );
    this.positionHardwareCursor(cursorPos, newLines.length);

// packages/coding-agent/src/core/system-prompt.ts
import { getDocsPath, getExamplesPath, getReadmePath } from '../config.ts';
import { formatSkillsForPrompt, type Skill } from './skills.ts';

export interface BuildSystemPromptOptions {
  customPrompt?: string; // 自定义 SystemPrompt
  selectedTools?: string[]; // 工具集合，默认：[read, bash, edit, write]
  toolSnippets?: Record<string, string>; // 可选的，工具 Snippet
  promptGuidelines?: string[];
  appendSystemPrompt?: string; // 追加到 SystemPrompt 的内容
  cwd: string; // 工作目录
  contextFiles?: Array<{ path: string; content: string }>; // 上下文文件
  skills?: Skill[]; // skills
}
// 构建 SystemPrompt 的方法，AgentSession 内部会调用
export function buildSystemPrompt(options: BuildSystemPromptOptions): string {
  const {
    customPrompt,
    selectedTools,
    toolSnippets,
    promptGuidelines,
    appendSystemPrompt,
    cwd,
    contextFiles: providedContextFiles,
    skills: providedSkills
  } = options;
  const promptCwd = cwd.replace(/\\/g, '/');
  const appendSection = appendSystemPrompt ? `\n\n${appendSystemPrompt}` : '';
  const contextFiles = providedContextFiles ?? [];
  const skills = providedSkills ?? [];
  // 如果有自定义 SystemPrompt，使用 customPrompt
  if (customPrompt) {
    let prompt = customPrompt;
    if (appendSection) {
      prompt += appendSection;
    }
    if (contextFiles.length > 0) {
      prompt += '\n\n<project_context>\n\n';
      prompt += 'Project-specific instructions and guidelines:\n\n';
      for (const { path: filePath, content } of contextFiles) {
        prompt += `<project_instructions path="${filePath}">\n${content}\n</project_instructions>\n\n`;
      }
      prompt += '</project_context>\n';
    }
    const customPromptHasRead =
      !selectedTools || selectedTools.includes('read');
    if (customPromptHasRead && skills.length > 0) {
      prompt += formatSkillsForPrompt(skills);
    }
    prompt += `\nCurrent working directory: ${promptCwd}\n`;
    return prompt;
  }
  /**
   * 所以，README.md、docs/*、examples/*
   * 会在 SystemPrompt 中被提到
   */
  const readmePath = getReadmePath();
  const docsPath = getDocsPath();
  const examplesPath = getExamplesPath();
  // 处理可用工具
  const tools = selectedTools || ['read', 'bash', 'edit', 'write'];
  const visibleTools = tools.filter(name => !!toolSnippets?.[name]);
  const toolsList =
    visibleTools.length > 0
      ? visibleTools.map(name => `- ${name}: ${toolSnippets![name]}`).join('\n')
      : '(none)';
  const guidelinesList: string[] = [];
  const guidelinesSet = new Set<string>();
  const addGuideline = (guideline: string): void => {
    if (guidelinesSet.has(guideline)) {
      return;
    }
    guidelinesSet.add(guideline);
    guidelinesList.push(guideline);
  };
  const hasBash = tools.includes('bash');
  const hasGrep = tools.includes('grep');
  const hasFind = tools.includes('find');
  const hasLs = tools.includes('ls');
  const hasRead = tools.includes('read');
  // 添加一些指南说明
  if (hasBash && !hasGrep && !hasFind && !hasLs) {
    addGuideline('Use bash for file operations like ls, rg, find');
  }
  for (const guideline of promptGuidelines ?? []) {
    const normalized = guideline.trim();
    if (normalized.length > 0) {
      addGuideline(normalized);
    }
  }
  // 默认指南
  addGuideline('Be concise in your responses');
  addGuideline('Show file paths clearly when working with files');
  const guidelines = guidelinesList.map(g => `- ${g}`).join('\n');
  // 默认的系统提示词
  let prompt = `You are an expert coding assistant operating inside pi, a coding agent harness. You help users by reading files, executing commands, editing code, and writing new files.

Available tools:
${toolsList}

In addition to the tools above, you may have access to other custom tools depending on the project.

Guidelines:
${guidelines}

Pi documentation (read only when the user asks about pi itself, its SDK, extensions, themes, skills, or TUI):
- Main documentation: ${readmePath}
- Additional docs: ${docsPath}
- Examples: ${examplesPath} (extensions, custom tools, SDK)
- When reading pi docs or examples, resolve docs/... under Additional docs and examples/... under Examples, not the current working directory
- When asked about: extensions (docs/extensions.md, examples/extensions/), themes (docs/themes.md), skills (docs/skills.md), prompt templates (docs/prompt-templates.md), TUI components (docs/tui.md), keybindings (docs/keybindings.md), SDK integrations (docs/sdk.md), custom providers (docs/custom-provider.md), adding models (docs/models.md), pi packages (docs/packages.md), environment variables (docs/environment-variables.md)
- When working on pi topics, read the docs and examples, and follow .md cross-references before implementing
- Always read pi .md files completely and follow links to related docs (e.g., tui.md for TUI API details)`;
  if (appendSection) {
    prompt += appendSection;
  }
  if (contextFiles.length > 0) {
    prompt += '\n\n<project_context>\n\n';
    prompt += 'Project-specific instructions and guidelines:\n\n';
    for (const { path: filePath, content } of contextFiles) {
      prompt += `<project_instructions path="${filePath}">\n${content}\n</project_instructions>\n\n`;
    }
    prompt += '</project_context>\n';
  }
  if (hasRead && skills.length > 0) {
    prompt += formatSkillsForPrompt(skills);
  }
  prompt += `\nCurrent working directory: ${promptCwd}`;
  return prompt;
}

权限检查

It has unrestricted access to your filesystem and can execute any command without permission checks or safety rails. No permission prompts for file operations or commands. No pre-checking of bash commands by Haiku for malicious content. Full filesystem access. Can execute any command with your user privileges.

Pi 可以无限制的访问文件系统，可以在没有权限检查的情况下执行任何命令。 对文件的操作和命令的执行，也没有任何权限提示。 也不会检查 bash 命令是否包含恶意指令。 所有操作都以用户账户权限执行。

As soon as your agent can write code and run code, it’s pretty much game over. The only way you could prevent exfiltration of data would be to cut off all network access for the execution environment the agent runs in, which makes the agent mostly useless.

Agent 会自己写代码并执行，所以权限检查除了会引入巨大的系统复杂度之外，毫无用处。唯一的方式就是将 Agent 运行在隔离的断网执行环境；但是，在那种环境下，Agent 也没了意义。

The core issue remains: if an LLM has access to tools that can read private data and make network requests, you’re playing whack-a-mole with attack vectors.

不提供 MCP 支持

Pi does not and will not support MCP.

作者曾经写过 《What If You Don’t Need MCP At All?》 。

Popular MCP servers like Playwright MCP (21 tools, 13.7k tokens) or Chrome DevTools MCP (26 tools, 18k tokens) dump their entire tool descriptions into your context on every session. That’s 7-9% of your context window gone before you even start working. Many of these tools you’ll never use in a given session.

MCP 内置了大量的工具，即使什么也不做，也会吃掉 7-9% 的上下文。

The alternative is simple: build CLI tools with README files. The agent reads the README when it needs the tool, pays the token cost only when necessary (progressive disclosure), and can use bash to invoke the tool.

作者推荐使用 skill 这种渐进式披露的工具来替换 MCP。

不支持后台运行 bash

There’s no built-in way to start a dev server, run tests in the background, or interact with a REPL while the command is still running.

This is intentional. Background process management adds complexity: you need process tracking, output buffering, cleanup on exit, and ways to send input to running processes.

Pi 故意不支持的，后台进程会增加系统复杂度。而且，你看不到后台进程到底在做什么。

作者推荐使用 tmux 。

没有 SubAgent

It’s a black box within a black box.

Context transfer between agents is also poor. The orchestrating agent decides what initial context to pass to the sub-agent, and you generally have little control over that. If the sub-agent makes a mistake, debugging is painful because you can’t see the full conversation.

SubAgent 的可观察性存在问题：

  • 你不知道 SubAgent 拿到的什么上下文，也控制不了；
  • 看不到 SubAgent 的完整轨迹，debugging 不方便。

I’m not dismissing sub-agents entirely. There are valid use cases. My most common one is code review: I tell pi to spawn itself with a code review prompt (via a custom slash command) and it gets the outputs.
